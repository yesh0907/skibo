Development Environment · Lesson 0014

Make orb setup converge

A reliable remote environment does expensive work once, verifies the restored state cheaply, and keeps wake-up repair nearly instantaneous.

Completed slice: Amp orb lifecycle setup

Separate installation from wake-up repair

SetupInstall locked Bun packages and pinned Playwright Chromium.
SnapshotPreserve packages, browser binaries, and caches for fresh orbs.
ResumeRepair only expiring connections or authentication; install nothing.

Setup is allowed to download dependencies because Amp snapshots its result. Resume runs every time an orb wakes and has a ten-second waiting window, so this repository correctly leaves it as a fast no-op: there are no external databases, tunnels, or credentials to restore.

Idempotence turns stale snapshots into an optimization

cold setup: bun install + Chromium download  → about 20 seconds
warm setup: lockfile check + browser check   → under 1 second
resume: no repair work                       → immediate

bun install --frozen-lockfile makes the lockfile authoritative. Playwright's installer similarly exits quickly when its exact browser build is already cached. Running setup twice proves that a stale snapshot can be refreshed without duplicate configuration or repeated downloads.

Verify across the same process boundary production uses. The browser was installed correctly, but Playwright's nested web-server shell could not resolve a package-local wrangler through bun run dev. Calling bunx wrangler at that boundary made binary resolution explicit, and the real acceptance suite then proved Chromium, Wrangler, and Durable Objects worked together.
