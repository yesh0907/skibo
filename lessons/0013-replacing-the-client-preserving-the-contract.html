Replace the client, preserve the contract

A framework migration succeeds when users gain new internals without having to relearn the product.

Completed slice: React root promotion with UI parity

Parity is a behavioral contract

StructureKeep the familiar lobby, table regions, cards, and overlays.
AffordancePreserve pointer thresholds, keyboard selection, and focus recovery.
AuthorityLet React consume the same server-provided legal commands and private views.

Copying colors alone would preserve a screenshot while breaking the game. This migration treats markup classes, responsive breakpoints, enabled and disabled controls, focus behavior, and real drag gestures as one product contract. React changes ownership of rendering and state; it does not change what a player must understand.

One production surface prevents drift

/react   /   308

The root URL now serves the React bundle, and the temporary migration path redirects to it. Removing the old static client matters: two independently evolving UIs would make every interaction fix, accessibility improvement, and transport change a synchronization problem.

The highest-value acceptance test performs the gesture. A click-based shortcut can prove command wiring while missing broken drag sensors, viewport clipping, or overlays. The browser test now moves the pointer from a legal card to a legal pile and observes the opponent update.

Retrieve the invariants

Why keep the old CSS class vocabulary?

It lets the proven visual and responsive system remain stable while React replaces implementation ownership. The migration can then distinguish a deliberate redesign from an accidental regression.

Why redirect /react/ instead of serving both paths?

A single canonical URL avoids duplicate product surfaces and stale links. A permanent redirect preserves migration compatibility without preserving a second implementation.
