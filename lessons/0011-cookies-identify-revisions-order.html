Skip-Bo HTTP Integration · Lesson 0011

Cookies identify; revisions order

A multiplayer request is safe only when the server knows both who is acting and which durable snapshot they acted from.

Completed slice: integrated Phase 3 HTTP application

Two independent proofs cross the boundary

CookieMaps the request to one private room player.
RevisionProves which room snapshot informed the action.
CommandMust still match the engine's exact legal set.

The HttpOnly cookie never enters React state. JavaScript stores only the public game id; the browser adds the game-scoped cookie to same-origin requests. The legacy bearer path remains temporary compatibility, not a second source of authority.

The Durable Object decides in a strict order

authenticate(playerCookie)
requireRevision(expectedRevision)
requireLegalCommand(command)
persist({ ...nextState, revision: revision + 1 })
return projectPlayerView(player)

Authentication prevents one player from reading another hand. The revision guard rejects decisions made from an old table. Exact command validation catches fabricated or no-longer-legal moves. Only a durable successful mutation advances the revision.

Privacy is projection, not cleanup: the Durable Object constructs a separate PlayerView for each caller. Opponent cardsInHand is null; tokens never appear in state or command responses.

Leave and exit mean different things

In a waiting room, Leave is a revisioned server mutation: remove the seat, revoke its token, advance once, clear the cookie, then clear local restoration state. After play starts, Exit is local navigation only; the authoritative game and seat remain available for reload recovery.

Retrieve the invariants

What changes after a stale or illegal command?

Nothing durable. The server returns a safe structured error, the room revision stays fixed, and a stale client fetches a current full view.

Why use isolated browser contexts in acceptance tests?

Each context owns an independent cookie jar. That reproduces distinct players and makes accidental cross-player session or hand leakage visible.
