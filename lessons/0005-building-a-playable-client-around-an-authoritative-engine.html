Skip-Bo Engine · Lesson 0005

Building a playable client around an authoritative engine

The terminal owns presentation and choice; the engine remains the only authority on which commands are legal and what they do.

Completed slice: local human-versus-bot CLI

The client loop has four jobs

Render Turn canonical state into build piles, hand cards, stock, discards, and opponent stock counts.
Choose Present exact legal commands and map one numbered answer back to the original command value.
Resolve Send the selected command through resolveCommand and render the returned snapshot. 
const commands = getLegalCommands(state)
const selected = commands[userChoice - 1]
state = resolveCommand(selected, state, { random }).nextState

Display text is not a command language

The CLI describes commands for a human, but it does not parse that text back into gameplay instructions. A numbered option retains the original discriminated-union value from the engine. This avoids creating a second, string-based rules boundary that could disagree with command validation.

Boundary rule: clients may choose among legal commands; they do not decide legality. The same rule will apply when the local human and bot are replaced by remote multiplayer clients.

Human policy and bot policy are peers

On a human turn, the client waits for a numbered choice. On a bot turn, the existing deterministic simulation policy chooses from the same legal-command array. Both choices pass through the same resolver, invariant checks, draw behavior, turn transition, and win detection.

Terminal I/O is injected

playLocalGame(...) receives asynchronous readLine and synchronous writeLine functions. The real adapter uses the terminal; tests supply small in-memory functions. Tests can therefore exercise invalid input, a human win, and bot-to-human handoff without mocking engine internals or launching a fragile pseudo-terminal.

Run the playable checkpoint

bun run play -- --seed 42 --stock 5 --name Yesh

Enter a listed number to act or q to quit. Five stock cards make a fast test game; changing the seed gives another reproducible deal.

Retrieve before revealing

Why retain the original command behind each number?

It prevents display wording and parsing logic from becoming another representation of the game rules.

What changes when play moves to the Durable Object?

The chooser becomes a remote player and snapshots cross a transport boundary, but legal-command calculation and resolution remain engine responsibilities.

Why inject terminal input and output?

The interaction workflow becomes testable through its public boundary while the actual terminal adapter stays very small.
